# 一、部署

## 1. 怎么启动

### 1.1 前置条件

| 依赖 | 用途 | 是否必须 |
|---|---|---|
| Node.js ≥ 20 | 扩展宿主运行时 | ✅ 必须 |
| VS Code ≥ 1.85 | 宿主 | ✅ 必须 |
| `npx`（随 npm） | 默认 agent 经它拉起 ACP 适配器 | ✅ 必须（除非把 `vac.agents` 改成绝对命令） |
| 可用的 agent CLI | 真正干活的 agent（Claude Code / Codex CLI） | ✅ 必须（`vac.agents` 里配的必须是能跑起来的命令） |
| `git` | 构建指纹取提交号 | ⬜ 可选（缺失则指纹显示 `nogit`） |

### 1.2 配置

配置全部在 VS Code 设置里（前缀 `vac.`），不需要 `.env`：

```
vac.agents                    agent 列表：名称 → { kind, command, args, env }
vac.autoApprovePermissions    ask（默认）| allowAll
vac.autoConnectOnOpen         打开聊天面板后是否自动连接（默认 true）
vac.restoreSessionsOnOpen     ask（默认）| always | never
vac.defaultWorkingDirectory   新会话默认工作目录（留空 = 工作区第一个文件夹）
vac.logTraffic                是否记录 ACP 协议流水（默认 true）
vac.customModels              额外注入 agent 的模型列表
vac.dashboard.enabled         是否扫描本机转录构建用量面板（默认 true）
vac.dashboard.claudeProjectsDir  Claude 转录目录覆盖（默认 ~/.claude/projects）
```

> 🔒 agent 的密钥/凭证应写进 `vac.agents.<name>.env`（设置是用户级的，不会进仓库），
> **不要写进仓库文件**。更好的做法：agent 要求认证时选它的 **API Key** 方式（如 Codex），
> 输入的 key 存进 VS Code 的 Secret Storage，不落 settings.json，下次启动自动复用。

### 1.2.1 Codex

- 默认配置 `npx -y @agentclientprotocol/codex-acp`（旧包 `@zed-industries/codex-acp` 已废弃；若你自己的
  `vac.agents` 里还写着旧包，激活时会弹窗提示一键替换，可选「不再询问」）。
- 已用 `codex login` 登录过的机器无需再认证。否则首次建会话会弹认证方式：**ChatGPT**（浏览器登录）或
  **API Key**（输入 key；留空则用 agent 环境里的 `CODEX_API_KEY` / `OPENAI_API_KEY`）。
- 换账号 / 清凭证：命令 `VAC: Log Out of Agent`（或 Agents 树右键），同时清掉存的 API key。
- Codex 的模型、推理强度、审批/沙箱模式都在输入卡的选择器里；自定义模型走 Codex 自己的
  `~/.codex/config.toml`（`vac.customModels` 只对 Claude 生效）。

### 1.3 启动

```bash
npm install
npm run dev:host        # 编译 + 打开 Extension Development Host
```

宿主窗口内改完代码按 `Ctrl+R` 重载即可生效（不需要重启宿主）。

要断点调试就回仓库窗口按 `F5`（读 `.vscode/launch.json`）。

> ⚠️ **首次启动的常见现象**：日志里会出现 npx 下载适配器的输出（`[<agent> stderr]`），
> 那是它在装包，等它跑完即可；这段时间面板显示「Connecting…」属正常。

## 2. 怎么用（核心功能）

### 2.1 连接 agent 并开聊

1. 打开活动栏 **VAC** → **Agents** 视图，点某个 agent 行的插头图标（或命令面板 `VAC: Connect to Agent`）。
2. 展开该 agent 可以看到历史会话；点会话即打开（能重放就重放，否则轻量恢复）。
3. 在 **Chat** 视图里输入并发送；工具调用、权限卡片、表单都会渲染在记录里。

> ⚠️ 多个 agent 可以同时连着，各自有各自的会话；切换 agent 不会断开原来的那个。

### 2.2 侧边栏 / 编辑区两个聊天面

- 侧边栏 Chat 视图与编辑区标签页**共享同一份记录**，关掉再打开不丢内容。
- 编辑区入口：命令 `VAC: Open Chat in Editor Area`，或聊天视图标题栏的按钮。
- 两个面各自记着自己的焦点会话，互不干扰。

### 2.3 Dashboard（用量统计）

- 打开 VAC 容器的 **Dashboard** 视图即可看到今日 / 7 天 / 30 天的 token 与成本估算、
  30 天趋势、按模型与项目的拆分、连接状态与最近会话。
- 首次打开会扫描本机转录，数据量大时先显示「扫描中」，完成后自动刷新。
- 点每条记录区右上角的刷新按钮（或命令 `VAC: Refresh Dashboard`）可强制重算。

> ⚠️ **成本是估算**：按等价 API 价格计算，订阅用户并不按此付费；未知模型计入「未定价」而非 0 成本。

### 2.4 轮次中补发消息

当 agent 声明支持 steering 时，轮次进行中再发一条消息会**追加到当前轮次**而不是排成新一轮。
若 agent 回答「没有在跑的轮次」，客户端会自动回落成普通发送。

# 二、维护

## 3. 数据 / 配置文件在哪

| 文件 | 内容 | 位置 |
|---|---|---|
| 扩展日志 | 全部宿主日志（含协议流水的镜像） | `~/.vac/vac.log`（超 5 MB 轮转为 `vac.log.1`） |
| 用量索引 | Dashboard 的聚合结果与文件游标 | `<globalStorage>/usage-index.json` |
| 会话历史缓存 | 本机客户端侧的会话列表（按 agent + 目录分桶） | 扩展的 `workspaceState`，key `vac.sessionHistory.v1` |
| 面板偏好 | 标签顺序、大纲宽度、自动连接开关等 | 扩展的 `globalState` |
| Claude 转录（只读） | Dashboard 的用量来源 | `$CLAUDE_CONFIG_DIR/projects`，默认 `~/.claude/projects/**/*.jsonl` |
| Codex 转录（只读） | Dashboard 的用量来源 | `$CODEX_HOME/sessions`，默认 `~/.codex/sessions/**/rollout-*.jsonl` |
| agent API key | 认证时输入的 key | VS Code Secret Storage（`vac.apiKey.<agent 名>`），登出时删除 |

> `~/.vac` 可用环境变量 `VAC_HOME` 改到别处。

## 4. 更新 / 刷新 / 重建

```bash
npm run compile      # 重新打包（改了源码后）
npm run dev:host     # 或起宿主，窗口内 Ctrl+R
```

Dashboard 的数据会增量更新（只读文件新增的字节）。要**从头重建**用量索引，删掉
`<globalStorage>/usage-index.json` 后刷新 Dashboard 即可。

## 5. 备份 / 迁移 / 重置

- **备份**：`~/.vac/vac.log`、`<globalStorage>/usage-index.json`，以及扩展的 `workspaceState`
  （会话历史缓存）。真正的会话内容在 agent 自己的目录里（`~/.claude`、`~/.codex`）。
- **迁移**：以上文件随机器搬即可；会话能否恢复取决于 agent 侧是否仍认得该会话。
- **重置**：删掉 `usage-index.json` 会重建统计；在 Agents 树里对一条会话右键
  **Delete Session** 可**真删除**它（agent 侧发 `session/delete` + 清本地缓存）。

> ⚠️ 重置前建议先备份；`vac.sessionHistory.v1` 是 Memento key，改名会导致历史缓存整体丢失。

## 6. 构建 / 发布

| 操作 | 命令 | 产物 |
|---|---|---|
| 开发构建 | `npm run compile` | `dist/extension.js` |
| 生产构建 | `npm run package` | `dist/extension.js`（压缩、外置 sourcemap） |
| 打包安装包 | `npm run vsix` | `release/<name>-<version>.vsix`（按 `.vscodeignore` 排除源码与文档） |
| 重新生成图标 | `npm run icon` | `resources/icon.svg`（侧边栏）与 `resources/icon.png`（插件徽标＋编辑区标签页） |

> 图标是**生成物**：几何定义写在 `scripts/make-icon.mjs` 里，改外观改那里再重跑，不要手改产物。
> 加 `--preview`（`node scripts/make-icon.mjs --preview`）会额外把 128/64/48/32/24/16 六个尺寸的
> 预览图写到系统临时目录，方便目视核对。

> 打包脚本 `scripts/package-vsix.mjs` 会先建好 `release/`（vsce 的 `--out` 目录不存在时不会自建），
> 再调本地 vsce；仓库根目录不再产生 `.vsix`。额外参数可透传，如 `npm run vsix -- --pre-release`。

> ⚠️ 新增顶层目录必须同步 `.vscodeignore`，否则会被打进 `.vsix` 发给用户。

# 三、调试

## 7. 行为不对 / 页面没反应（出问题怎么自查）

1. **先确认跑的是哪份代码**：输出通道 `VAC` 的第一行与聊天 webview 客户端启动日志里都有**构建指纹**
   （版本 · git sha · 打包时间 · bundle 哈希）。两处哈希一致才说明「窗口跑的是当前构建」；
   日志里根本没有这行 = 窗口没重载。
2. **看输出通道**：`VAC`（常规/错误）与 `VAC Traffic`（ACP 协议请求/通知/响应的原始载荷）。
   两个通道都同时落盘到 `~/.vac/vac.log`，排查时**直接读文件**比让人复制粘贴快。
3. **看 stderr**：agent 起不来时，用户唯一能看到的「为什么」就在 `[<agent> stderr]` 那几行里。
4. **记录区布局类问题**：不要靠推理，用 `node scripts/preview-records.mjs` 无头截图**自己看**。

## 8. 常见问题（FAQ）

**Q：点了连接没反应，或者一直停在「Connecting…」？**
A：看 `VAC` 通道与 `[<agent> stderr]`。最常见的是 npx 正在下载适配器（等它跑完），
或 `vac.agents` 里配的命令在本机 PATH 上不存在（类 Unix 走 login shell，IDE 环境变量可能不含 nvm）。

**Q：Escape 不能取消当前轮次？**
A：取消需要具备两个条件：确实有轮次在跑（`vac.turnInProgress`），且焦点在聊天界面内
（侧边栏 Chat 视图或编辑区聊天标签页）。在别的编辑器里按 Escape 不会触发取消。

**Q：Dashboard 显示「未定价」？**
A：该模型不在内置价格表里。补价格见 `src/dashboard/usage/pricing.ts`（`PRICING_AS_OF` 标注了数据口径）。

**Q：会话列表里看不到某个历史会话？**
A：agent 支持 `session/list` 时以 agent 为准；否则用本机缓存，而缓存是 `workspaceState` 作用域的，
**换工作区就看不到**在别的工作区产生的记录。跨目录打开请从记录区的历史选择器走。

## 9. 怎么跑测试 / 看测在哪

```bash
npm run test:unit     # vitest：纯逻辑（core 的策略、SessionStore、AgentProfile、TailBuffer、dashboard 解析与聚合）
npm test              # mocha：真实 Extension Host（激活、命令注册、设置默认值、聊天面板协议）
```

改了纯逻辑模块（`core/SessionStore`、`core/cwd`、`agents/`、`utils/TailBuffer`、`dashboard/usage/`）
务必跑 `test:unit`；改了激活、命令、设置或面板协议务必跑 `npm test`。
