# 01 · 技术栈说明

> 面向使用者/维护者：本项目用了哪些技术、为什么这么选、各自负责什么。
> 代码在哪、怎么连，见 [`../ARCHITECTURE.md`](../ARCHITECTURE.md)。

## 总览

| 用途 | 选型 | 为什么 |
|---|---|---|
| 语言 / 运行时 | TypeScript + Node ≥ 20 | VS Code 扩展的标准栈；严格模式（`tsconfig.json`）挡住大量低级错误 |
| 宿主 API | VS Code Extension API ≥ 1.85 | 树视图 / webview / 状态栏 / 命令 / 设置都由它提供 |
| 协议 | `@agentclientprotocol/sdk`（ACP） | 与 agent CLI 走 stdio 上的 JSON-RPC；换 agent 不用换客户端 |
| agent 进程 | `node:child_process` | 把 agent CLI 拉成子进程（`npx` 拉起 Claude Code / Codex 的 ACP 适配器） |
| 构建 | esbuild | 单文件 `dist/extension.js`，毫秒级打包；构建时注入指纹常量 |
| 纯逻辑测试 | vitest | 秒级、可直接在裸 node 下跑（要求被测模块**不 import `vscode`**） |
| 集成测试 | `@vscode/test-cli` + mocha | 在真实 Extension Host 里验证激活、命令注册与面板协议 |
| Lint / 类型 | ESLint flat config（`--max-warnings 0`）+ `tsc --noEmit` | 零警告闸门 |
| Markdown 渲染 | `marked` | 聊天记录里的 markdown 渲染（配白名单，见 `ui/chat/markdown.ts`） |
| 第三方图表 | 无 | Dashboard 的趋势图用内联 SVG 手写，不引图表库 |

## 各组件职责分工

- **`core/`（传输与编排）**：进程生命周期、ACP 握手、连接与能力缓存、会话状态机、历史缓存。
  只管「和 agent 打交道」，不认识任何 UI 类型。
- **`handlers/`（客户端能力）**：实现 ACP 要求客户端提供的能力（读写文件、终端、权限、表单），
  以及两个「桥」——权限与表单的**唯一出口**（桥内部决定走面板卡片还是弹框，因此桥本身不 import
  vscode 的 UI 类型，方便单测）。
- **`ui/`（视图层）**：侧边栏树、状态栏、聊天面板子系统。所有数据都来自 `SessionManager` 的
  公开方法与事件，不直接碰连接与进程。
- **`dashboard/`（统计层）**：`usage/` 是纯逻辑（解析、去重、聚合、定价），`DashboardViewProvider`
  负责视图与消息。数据来自本机的 agent 转录文件，与 ACP 链路**完全解耦**。
- **`agents/` + `config/`**：agent 专有差异（目前是会话请求的 `_meta`）与配置读取。
  **加一个 agent 只动这里 + `package.json`，不往 UI 加分支。**

## 配置与运行

- 所有可调参数集中在 VS Code 设置里，前缀 **`vac.`**（`package.json` 的 `contributes.configuration`
  是单一源；读取入口是 `src/config/AgentConfig.ts`）。
- 运行：`npm run dev:host`（编译 + 启动 Extension Development Host）；统一管理脚本 `sh manager.sh help`。
- 测试：`npm run test:unit`（vitest）/ `npm test`（真实宿主）；lint `npm run lint`；类型 `npm run typecheck`。
- 构建：`npm run compile`（开发）/ `npm run package`（生产），产物都是 `dist/extension.js`。
